# Java FFM Bindings – Implementation Plan

> **API**: Java Foreign Function & Memory (FFM) API — JEP 454, finalized in JDK 22.  
> **Goal**: Provide idiomatic Java bindings to `libastarte_device_sdk_bindings.so` that mirror the structure of the existing Python/CFFI bindings.

---

## Background & Context

The Rust crate (`astarte-device-sdk-bindings`) compiles to a shared library and exposes a C ABI declared in `target/header.h`. The Python package under `python/` already wraps this library with CFFI. We will build an equivalent Java package in this folder using the modern **Java FFM API** (`java.lang.foreign.*`), available without preview flags since **JDK 22**.

Key design principles carried over from the Python bindings:
- Load the shared library at runtime (no compile-time JNI glue code).
- Use callback-based async operations (the C API fires a callback on completion; Java wraps this with `CompletableFuture`).
- `UserData` is a raw `void *` that the Rust side passes back to the callback; we use it to carry a `MemorySegment` that points to a boxed Java object acting as a handle.

## High-Level Architecture

```
java/
├── astarte/                          ← new Gradle sub-project (library)
│   ├── build.gradle.kts
│   └── src/main/java/org/astarte/device/
│       ├── NativeLoader.java         ← library discovery & Linker setup
│       ├── DeviceConfig.java         ← config value objects + layout builders
│       ├── DeviceData.java           ← data union layout builder & decoder
│       ├── DeviceEvent.java          ← decoded event value object
│       ├── DeviceObject.java         ← named value map for object sends
│       ├── AstarteDevice.java        ← main public API class
│       └── internal/
│           ├── Layouts.java          ← all MemoryLayout constants
│           ├── CallbackRegistry.java ← keeps callback stubs alive (GC guard)
│           └── ResultDecoder.java    ← decodes NativeStringResult_bool etc.
└── settings.gradle.kts               ← add "astarte" to include(...)
```

NOTE: The existing `app/`, `list/`, and `utilities/` sub-projects are scaffolding generated by
`gradle init`. They should not be changed; the new code lives exclusively in the new `astarte/`
sub-project. `app/` may later be updated to use `astarte/` as a demonstration.

### Step 3 – `Layouts.java` — memory layout constants

**Package**: `org.astarte.device.internal`

This class is a pure constants holder. It declares one `MemoryLayout` (or `ValueLayout` /
`StructLayout` / `UnionLayout`) for every type that appears in `header.h`. These layouts encode
the C struct field offsets so that `MemorySegment.get*()` calls use the right byte positions.

Key layouts to define (derived from the header):

| C type | Java MemoryLayout | Notes |
|---|---|---|
| `NativeDeviceHandle` | `ValueLayout.ADDRESS` | opaque pointer |
| `NativeMqttConnectionConfig` | StructLayout of 4 ADDRESS fields | device_id, cred_secr, realm, pairing_url |
| `NativeGrpcConnectionConfig` | StructLayout of 1 ADDRESS field | message_hub_addr |
| `NativeConnectionConfig` | StructLayout with tag + union padding | tag is JAVA_INT; union as wide as largest member |
| `NativeGenericDeviceConfig` | StructLayout with 2 ADDRESS + 1 JAVA_LONG | interfaces_dir, channel_size, writable_dir |
| `NativeDeviceConfig` | StructLayout of connection + generic | |
| `NativeStringResult_bool` | StructLayout with tag + union | tag JAVA_INT; ok is JAVA_BOOLEAN; err is ADDRESS |
| `NativeDeviceData` | large StructLayout with tag + union | tag is JAVA_INT (enum); union wide enough for largest variant |
| `CArray_*` | StructLayout of ADDRESS data_ptr + JAVA_LONG size | generic pattern |
| `NativeObjectEntry` | StructLayout of ADDRESS path + NativeDeviceData value | |
| `NativeValue` | StructLayout with tag + union | largest body is Object_Body |
| `NativeDeviceEvent` | StructLayout of 2 ADDRESS + NativeValue data | |
| `NativeIndividualSend` | StructLayout of 2 ADDRESS + NativeDeviceData + NativeOption_NativeTimestamp | |
| `NativeObjectSend` | StructLayout of 2 ADDRESS + CArray_NativeObjectEntry + NativeOption_NativeTimestamp | |
| `NativeSetProperty` | StructLayout of 2 ADDRESS + NativeDeviceData | |
| `NativePropertyIdentifier` | StructLayout of 2 ADDRESS | |
| `NativeOption_NativeDeviceData` | StructLayout with tag + optional NativeDeviceData | |

WARNING: Union layout sizes and padding must exactly match the compiled Rust struct sizes. Use
a test helper that validates key struct sizes against the running library (e.g. allocate via
the library and check pointer delta), or cross-check against `cbindgen` output.

### Step 4 – `NativeLoader.java` — library loading & linker

**Package**: `org.astarte.device`

Responsibilities:
- Discover the shared library path (env var `ASTARTE_SDK_LIB_PATH`, then `target/debug/`,
  then `target/release/`).
- Open a `SymbolLookup` via `SymbolLookup.libraryLookup(path, Arena.global())`.
- Provide a `Linker` instance (`Linker.nativeLinker()`).
- Cache `MethodHandle` instances for every exported C function (looked up eagerly at
  class-init time).

The method handles correspond to these C signatures (excerpt):

```java
// device_handle_init() -> NativeDeviceHandle (= pointer)
MethodHandle DEVICE_HANDLE_INIT = linker.downcallHandle(
    lookup.find("device_handle_init").orElseThrow(),
    FunctionDescriptor.of(ValueLayout.ADDRESS)
);

// device_handle_connect(handle, config*, build_cbk, build_data, loop_cbk, loop_data)
MethodHandle DEVICE_HANDLE_CONNECT = linker.downcallHandle(
    lookup.find("device_handle_connect").orElseThrow(),
    FunctionDescriptor.ofVoid(
        ValueLayout.ADDRESS,  // handle
        ValueLayout.ADDRESS,  // config*
        ValueLayout.ADDRESS,  // build_cbk (function pointer)
        ValueLayout.ADDRESS,  // build_user_data
        ValueLayout.ADDRESS,  // loop_cbk
        ValueLayout.ADDRESS   // loop_user_data
    )
);
// ... (one entry per exported function)
```

### Step 5 – `CallbackRegistry.java` — keeping upcall stubs alive

**Package**: `org.astarte.device.internal`

The FFM API creates "upcall stubs" via `Linker.upcallStub(...)`. These are `MemorySegment`s
that point to JVM-generated native trampolines. They **must not be GC'd** while Rust may still
invoke them.

`CallbackRegistry` is a thread-safe `Set` that holds strong references to all upcall stubs
until explicitly released. When a callback fires, the callback itself removes its stub from
the registry.

For `UserData`, use a `ConcurrentHashMap<Long, Object>` keyed by the `MemorySegment` address.
Allocate a small sentinel segment from `Arena.global()` per callback, store its address as
`user_data`, and resolve it back to the Java payload inside the upcall handler.

---

### Step 6 – `ResultDecoder.java` — decode `NativeStringResult_*`

**Package**: `org.astarte.device.internal`

Helper static methods that take a `MemorySegment` pointing to any `NativeStringResult_*`
struct and return either the payload or throw an `AstarteException`. Three flavors needed:

- `decodeBoolResult(MemorySegment seg)` → void or throws
- `decodeEventResult(MemorySegment seg)` → `DeviceEvent` or throws
- `decodePropertyResult(MemorySegment seg)` → `Optional<DeviceData>` or throws

### Step 10 – `AstarteDevice.java` — main public API

**Package**: `org.astarte.device`

```java
public class AstarteDevice implements AutoCloseable {

    private final MemorySegment handle; // NativeDeviceHandle (opaque pointer)
    private final Arena arena;          // owns long-lived native memory for this device

    public AstarteDevice() { ... } // calls device_handle_init()

    /** Returns a CompletableFuture<Void> that completes when connected. */
    public CompletableFuture<Void> connect(DeviceConfig config) { ... }

    /** Returns a CompletableFuture<Void> that completes when disconnected. */
    public CompletableFuture<Void> disconnect() { ... }

    /** Returns a CompletableFuture<DeviceEvent> for the next received event. */
    public CompletableFuture<DeviceEvent> receive() { ... }

    public CompletableFuture<Void> sendIndividual(
        String iface, String path, DeviceData data,
        Instant timestamp) { ... }  // timestamp may be null

    public CompletableFuture<Void> sendObject(
        String iface, String path, DeviceObject obj,
        Instant timestamp) { ... }  // timestamp may be null

    public CompletableFuture<Void> setProperty(
        String iface, String path, DeviceData value) { ... }

    public CompletableFuture<Void> unsetProperty(String iface, String path) { ... }

    public CompletableFuture<Optional<DeviceData>> getProperty(
        String iface, String path) { ... }

    @Override
    public void close() { ... } // calls device_handle_free()
}
```

Each method:
1. Allocates native structs in a shared or confined `Arena`.
2. Creates a `CompletableFuture`.
3. Builds an upcall stub registered in `CallbackRegistry`.
4. Packs a Java payload object into the handle map; passes its address as `UserData`.
5. Invokes the appropriate `MethodHandle` from `NativeLoader`.
6. The upcall handler resolves the future and removes the stub from the registry.

## Key FFM API Classes Used

| FFM Class | Role |
|---|---|
| `java.lang.foreign.Arena` | Scoped memory allocator (replaces manual malloc/free) |
| `java.lang.foreign.MemorySegment` | A typed, bounded view of native memory |
| `java.lang.foreign.MemoryLayout` sub-types | Describes C struct/union/array layouts |
| `java.lang.foreign.Linker` | Bridges Java <-> native; creates downcall and upcall handles |
| `java.lang.foreign.SymbolLookup` | Resolves C symbol names to native addresses |
| `java.lang.foreign.FunctionDescriptor` | Declares C function signatures in terms of MemoryLayouts |
| `java.lang.invoke.MethodHandle` | Represents a downcall or upcall to/from native code |

## Notes & Caveats

- **Callback threading**: Rust invokes callbacks from its own Tokio threads. Java's
  `CompletableFuture::complete` is thread-safe, but framework-specific thread affinity must
  be handled by the caller (e.g., `thenAcceptAsync(..., executor)`).

- **Memory lifetime**: Any `Arena` that owns structs passed to a C function must stay open
  until the callback fires. Use `Arena.ofShared()` for structs that outlive the calling
  method, and close the arena explicitly inside the callback.

- **`UserData` pattern**: FFM has no built-in "handle" mechanism like CFFI's `ffi.new_handle`.
  The recommended pattern is: allocate a small 1-byte sentinel `MemorySegment` from
  `Arena.global()` per callback, store `Long address -> Object payload` in a
  `ConcurrentHashMap`, pass the address as `void *user_data`, and look it up in the upcall.

- **`jextract` is optional**: The `jextract` tool from Project Panama can auto-generate
  the `Layouts` and `NativeLoader` boilerplate from `target/header.h`. This is a good
  option if the header evolves frequently. The plan above keeps hand-written layouts so
  there is no extra tooling dependency, but the team may switch to `jextract`-generated
  code at any point.
