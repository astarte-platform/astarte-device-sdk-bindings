# astarte-sdk-android

Android/Kotlin bindings for the [Astarte Device SDK](https://github.com/astarte-platform/astarte-device-sdk-rust), generated by [BoltFFI](https://www.boltffi.dev/docs/getting-started).

## Generating the Android bindings

The Kotlin source under `app/src/main/kotlin/org/astarte/device/sdk/bindings/` is produced by BoltFFI. To regenerate from scratch:

```sh
# From the repo root — Android SDK/NDK must be set up
get_android   # sources $HOME/Android/Sdk/export.sh (sets ANDROID_HOME, ANDROID_NDK, PATH)
export JAVA_HOME="/usr/lib/jvm/java-8-openjdk-amd64"
boltffi pack android
```

Output lands in `dist/android/`:
- `jniLibs/{arm64-v8a,armeabi-v7a,x86_64,x86}/libastarte-device-sdk-bindings.so` — native libs per ABI
- `kotlin/org/astarte/device/sdk/bindings/AstarteDeviceSdkBindings.kt` — generated Kotlin source
- `include/astarte-device-sdk-bindings.h` — C header (for reference)

Copy the native libs and Kotlin source into the app module:

```sh
cp -r dist/android/jniLibs/arm64-v8a  astarte-sdk-android/app/src/main/jniLibs/
cp -r dist/android/jniLibs/x86_64     astarte-sdk-android/app/src/main/jniLibs/

cp dist/android/kotlin/org/astarte/device/sdk/bindings/AstarteDeviceSdkBindings.kt \
   astarte-sdk-android/app/src/main/kotlin/org/astarte/device/sdk/bindings/
```

Then re-apply the post-generation fixes described below.

## Post-generation fixes

Apply these edits to the **copied** `AstarteDeviceSdkBindings.kt` (not the `dist/` original):

**1. Missing `kotlinx.coroutines` imports** — add after the existing `kotlinx.coroutines.*` import:

```kotlin
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.Job
import kotlinx.coroutines.SupervisorJob
import kotlinx.coroutines.launch
```

**2. Shadowed stdlib types in `AstarteVal`** — qualify four data class property types:

```kotlin
data class Double(val `value`: kotlin.Double) : AstarteVal()
data class Boolean(val `value`: kotlin.Boolean) : AstarteVal()
data class DoubleArray(val `value`: kotlin.DoubleArray) : AstarteVal()
data class BooleanArray(val `value`: kotlin.BooleanArray) : AstarteVal()
```

**3. `interface` keyword as parameter name** — escape with backticks in the `Native` object's `external fun` declarations:

```kotlin
// Change:  , interface: ByteBuffer,
// To:      , `interface`: ByteBuffer,
```

**4. `run {}` in secondary constructor** — qualify the inner `run` block to avoid a `this`-before-init error:

```kotlin
// In AstarteDevice constructor, change inner bare `run {` to:
kotlin.run {
```

## Build and test

**Prerequisites:** Android Studio or the Android command-line tools, JDK 8

```sh
export JAVA_HOME="/usr/lib/jvm/java-8-openjdk-amd64"
export ANDROID_HOME=$HOME/Android/Sdk

cd astarte-sdk-android

# Run local JVM unit tests (no device needed)
./gradlew test

# Build debug APK
./gradlew assembleDebug
```

---

## Deploy and run

**1. Copy the native libraries** (if not already done — see Generating section above).

**2. Edit credentials** in `app/src/main/kotlin/org/astarte/device/sdk/example/MainActivity.kt` — replace the placeholder `realm`, `deviceId`, `credentialsSecret`, and `pairingUrl` values.

**3. Deploy to a connected device or emulator:**

```sh
./gradlew installDebug
```

The `.so` files are loaded automatically via `System.loadLibrary("astarte-device-sdk-bindings")` inside the generated `Native` object in `AstarteDeviceSdkBindings.kt`.

## API overview

```kotlin
import org.astarte.device.sdk.bindings.*

// Configure
val config = AstarteConfig(
    realm = "myrealm",
    deviceId = "device-id",
    credentialsSecret = "credentials-secret",
    pairingUrl = "http://api.astarte.example/pairing",
    ignoreSsl = false
)

// Connect and listen
val device = AstarteDevice(config, "path/to/interfaces")
thread {
    device.startListening(object : EventListener {
        override fun onConnected() { }
        override fun onDisconnected() { }
        override fun onDataReceived(`interface`: String, path: String, data: AstarteVal) { }
        override fun onObjectReceived(`interface`: String, path: String, entries: List<ObjectEntry>) { }
        override fun onPropertyReceived(`interface`: String, path: String, data: AstarteVal) { }
        override fun onPropertyUnset(`interface`: String, path: String) { }
    })
}

// Send data
device.send("com.example.Interface", "/path", AstarteVal.Integer(42))
device.send("com.example.Interface", "/path", AstarteVal.Double(3.14))
device.send("com.example.Interface", "/path", AstarteVal.IString("hello"))

device.disconenct()
device.close()
```

### AstarteVal variants

| Variant | Kotlin type |
|---|---|
| `AstarteVal.Double` | `kotlin.Double` |
| `AstarteVal.Integer` | `Int` |
| `AstarteVal.Boolean` | `kotlin.Boolean` |
| `AstarteVal.LongInteger` | `Long` |
| `AstarteVal.IString` | `String` |
| `AstarteVal.BinaryBlob` | `ByteArray` |
| `AstarteVal.DateTime` | `Long` (ms since epoch) |
| `AstarteVal.DoubleArray` | `kotlin.DoubleArray` |
| `AstarteVal.IntegerArray` | `IntArray` |
| `AstarteVal.BooleanArray` | `kotlin.BooleanArray` |
| `AstarteVal.LongIntegerArray` | `LongArray` |
| `AstarteVal.StringArray` | `Array<String>` |
| `AstarteVal.DateTimeArray` | `LongArray` |

> **Note:** `Double`, `Boolean`, `DoubleArray`, and `BooleanArray` variants use `kotlin.`-qualified types to avoid shadowing Kotlin/Java stdlib names — this is one of the post-generation fixes applied above.

## Notes

- The `disconenct()` method name is a typo inherited from the Rust FFI surface; it is preserved as-is to match the generated bindings exactly.
